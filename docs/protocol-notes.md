# LG webOS SSAP Protocol Notes & Technical Findings

## 1. Overview
LG Smart TVs running webOS communicate over the Second Screen Access Protocol (SSAP). SSAP is a JSON-RPC-styled WebSocket protocol running on:
- **Port 3000 (`ws://`)**: Standard unencrypted WebSocket (available on webOS 3.x - 6.x and most modern firmware on LAN).
- **Port 3001 (`wss://`)**: TLS-encrypted WebSocket. Usually uses a self-signed certificate generated by the TV firmware.

## 2. Pairing & Handshake (`register`)

### Initial Handshake
The client opens the WebSocket and sends:
```json
{
  "id": "register_0",
  "type": "register",
  "payload": {
    "forcePairing": false,
    "pairingType": "PROMPT",
    "manifest": {
      "manifestVersion": 1,
      "appVersion": "1.0.0",
      "signed": {
        "created": "20261101",
        "appId": "com.antigravity.lgremote",
        "vendorId": "antigravity",
        "localizedAppNames": { "": "LG Smart Remote" },
        "localizedVendorNames": { "": "Antigravity" },
        "permissions": [
          "LAUNCH",
          "CONTROL_AUDIO",
          "CONTROL_INPUT_TEXT",
          "CONTROL_MOUSE_AND_KEYBOARD",
          "READ_RUNNING_APPS"
        ],
        "serial": "antigravity-lgremote-001"
      },
      "permissions": [
        "LAUNCH",
        "CONTROL_AUDIO",
        "CONTROL_INPUT_TEXT",
        "CONTROL_MOUSE_AND_KEYBOARD",
        "READ_RUNNING_APPS"
      ]
    }
  }
}
```

### TV Response States
1. **Prompt Displayed on TV (`pairingType: PROMPT`):**  
   The TV prompts the user with an on-screen dialog: `"LG Smart Remote is requesting access"`. The TV sends:
   ```json
   {
     "id": "register_0",
     "type": "response",
     "payload": { "pairingType": "PROMPT", "returnValue": true }
   }
   ```
2. **PIN Code Displayed on TV (`pairingType: PIN`):**  
   The TV displays an 8-character numeric PIN on screen. The TV sends:
   ```json
   {
     "id": "register_0",
     "type": "response",
     "payload": { "pairingType": "PIN", "returnValue": true }
   }
   ```
   The client application prompts the user for the code and submits it via:
   ```json
   {
     "id": "register_1",
     "type": "request",
     "uri": "ssap://pairing/setPin",
     "payload": { "pin": "12345678" }
   }
   ```
   If valid, the TV responds with `"type": "registered"` containing the persistent `"client-key"`.
   If invalid, the TV responds with an error (`401 Unauthorized / Invalid PIN`).

3. **User Approves on TV (Prompt mode):**  
   When the user selects **Yes/Allow** with the physical Magic Remote, the TV emits:
   ```json
   {
     "id": "register_0",
     "type": "registered",
     "payload": {
       "client-key": "4a7f6c... (64 hex characters)"
     }
   }
   ```
4. **Reconnecting with Saved Key:**  
   On subsequent sessions, the client includes `"client-key": "<saved-key>"` in the register payload. The TV returns `"type": "registered"` immediately without showing an on-screen prompt or PIN.

## 3. Remote Key Dispatch & Pointer Socket
Directional navigation (UP, DOWN, LEFT, RIGHT, ENTER, BACK, HOME) in modern webOS requires a specialized binary/text socket:
1. Client requests the socket path:
   `ssap://com.webos.service.networkinput/getPointerInputSocket`
2. TV responds with:
   `{ "socketPath": "ws://192.168.1.50:3000/pointerInputSocket/..." }`
3. Client establishes a secondary WebSocket to `socketPath`.
4. Buttons are dispatched as newline-delimited text commands:
   `type:button\nname:UP\n\n`
   `type:button\nname:ENTER\n\n`
   `type:button\nname:HOME\n\n`

## 4. Phone-to-TV YouTube Search Sequence
1. Ensure the TV is paired and connected.
2. Launch YouTube via `ssap://system.launcher/launch` with `{ "id": "youtube.leanback.v4" }` (or discovered YouTube app ID).
3. The user must focus the search input field on the TV (an on-screen helper tip is displayed).
4. Send text to the active webOS IME buffer:
   `ssap://com.webos.service.ime/insertText` with `{ "text": "...", "replace": 0 }`
5. Send Enter to trigger the search query:
   `ssap://com.webos.service.ime/sendEnterKey`

## 5. Browser Mixed Content & Transport Restrictions
- **HTTPS to `ws://`**: Browsers enforce mixed-content blocking. If the remote web app is loaded from an `https://` origin (e.g. `https://myremote.vercel.app`), the browser blocks direct unencrypted WebSocket connections to `ws://192.168.1.x:3000`.
- **Self-signed TLS on Port 3001**: Connecting to `wss://192.168.1.x:3001` directly from a browser can fail due to self-signed TLS certificate rejection unless the user trusts the certificate or uses an HTTP/PWA origin.
- **Native Android Fallback**: When packaged in Capacitor / Android WebView with the native WebSocket transport plugin, these restrictions are bypassed.
